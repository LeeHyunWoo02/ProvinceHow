# EIS 고용행정통계 연동 명세 (job 컨텍스트 데이터 소스)

- 조사·작성일: **2026-08-28**
- 대상: EIS 고용행정통계 (`eis.work24.go.kr`) — 고용노동부/한국고용정보원
- 이 문서는 `docs/worknet-job-api.md`(워크넷 OPEN-API)와 `docs/work24-crawling-assessment.md`(스크래핑
  불가 판정)가 모두 막힌 뒤, **실제로 쓸 수 있는 대체 소스**를 확정하기 위한 실측 기록이다.
- 아래 "확인됨"은 전부 2026-08-28에 실제 호출·다운로드로 검증한 것이다. 검증하지 못한 것은
  **미확인**으로 표시했다. 추측으로 채우지 않았다.

## 0. 먼저 읽을 것

### 0-1. 왜 EIS 인가

| 소스 | 상태 |
| --- | --- |
| 고용24 OPEN-API (채용정보목록/상세) | **불가.** 사업자등록번호 필수. 사용자는 겸업금지로 등록 불가 |
| 공공데이터포털 워크넷 채용정보(3038225) | **불가.** 결국 고용24 인증키를 요구 |
| 사람인 / 원티드 | **불가.** 승인 필요, 신청 채널 미운영 |
| 직행 | **보류.** 2026-08 문의 결과 "개발 리소스 부족, OpenAPI 공개는 내년 예상" |
| **EIS 고용행정통계** | **가능.** 인증 없이 공개. 본 문서 대상 |

직행이 OpenAPI 를 열면 개별 공고 데이터가 다시 생긴다. **EIS 는 그때까지의 대체재가 아니라,
지역 비교 지표라는 별도 축으로 계속 쓸 값어치가 있다**(구인배수·연령대 분해는 공고 API 로 못 만든다).

### 0-2. 개별 채용공고는 EIS 로 못 만든다

EIS 는 집계 통계다. `JobVacancyItem` 이 요구하는 `title` `companyName` `detailUrl` `salaryText`
`expirationDate` 는 **존재하지 않는다.** 지역 상세의 공고 목록 영역은 직행 OpenAPI 가 열릴 때까지
비워두는 것이 맞다. 채우려 하면 데이터를 지어내게 된다.

### 0-3. 수집 경로는 두 개고, **통계표 다운로드를 채택**한다

| | OPEN API (§2) | 통계표 다운로드 (§3, **채택**) |
| --- | --- | --- |
| 인증 | 불필요 | 불필요 |
| 지역 단위 | 시군구 | 시군구 |
| 직종 해상도 | 대분류 10종 | **중분류 35~36종** |
| 호출 제약 | **IP 일일 한도 (~100~130회 추정)** | 없음 |
| 1개월치 확보 비용 | 7,072 회 | 파일 1개 |
| 자동화 | 가능 | **수동 다운로드** |

API 로 전국 1개월을 채우려면 272 시군구 × 성별 2 × 연령 13 = **7,072 회**가 필요한데 IP 한도가
그 100 분의 1 수준이다. **API 단독 전수 수집은 성립하지 않는다.**

## 2. OPEN API (보조 경로)

채택하지 않았지만 소량 온디맨드 조회에는 쓸 수 있다. 실측 스펙을 남긴다.

### 2-1. 엔드포인트 — **확인됨**

```
GET https://eis.work24.go.kr/opi/joApi.do
    ?apiSecd=OPIA          # 구인·구직 현황 (OPIB=피보험자, OPIC=실업급여)
    &rernSecd=XML          # XML 전용. JSON 지정 시 에러
    &rsdAreaCd=11110       # 시군구 5자리. 필수. 시도 2자리는 0건, 생략 불가
    &sxdsCd=M              # M/F. 필수
    &ageCd=01              # 01~12. 필수
    &closStdrYm=202607     # YYYYMM. 필수
    &bgnPage=1&display=100
```

- **인증키 파라미터가 없다.** 키 없이 200 + 정상 데이터.
- 응답은 **EUC-KR XML**.
- 최신 기준월 `202607` 응답 확인.
- **집계 코드가 없다.** 성별·연령 전체를 뜻하는 값이 없어 26개 조합을 모두 돌아 합산해야 한다.

### 2-2. 응답 필드 — **확인됨**

| 필드 | 의미 |
| --- | --- |
| `rsdAreaCd` / `rsdAreaCdNm` | 시군구 코드 / 명 |
| `ctpvCd` / `ctpvCdNm` | 시도 코드 / 명 |
| `wnetJsfcLrclCd` / `Nm` | 워크넷 직종 **대분류** (000000~900000, 10종) |
| `stdIndLrclCd` / `Nm` | 표준산업 대분류 |
| `newJoNmpr` | 신규구인인원 |
| `valdJoNmpr` | **유효구인인원** |
| `newJhntNmpr` | 신규구직건수 |
| `empmCt` | 취업건수 |
| `jsfcVerCd` | 직종분류 버전 (`2018`) |

### 2-3. 함정 — IP 단위 일일 호출 한도

약 350회 호출 후 아래로 전환됐고, 그 뒤로는 직전까지 성공하던 요청도 전부 같은 에러를 반환했다.

```xml
<baroone><error>HITS_EXCEEDED : 해당 사용자의 IP에서 조회할 수 있는 OPEN API 조회 횟수가 초과됐습니다.</error></baroone>
```

- 가이드 문서에 **수치가 명시돼 있지 않다.**
- 성공/실패 전환 지점으로 역산하면 **100~130회/일**로 추정된다. **미확인** — 정확한 한도를
  재려면 쿼터가 리셋된 날 첫 호출부터 카운트해야 한다.
- 에러 형태: `<baroone><error>CODE : 메시지</error></baroone>`. 다른 코드로 `NO_PARAM`,
  `RERN_SECD` 확인.

> **키가 없다고 무제한이 아니다.** 이 API 를 쓰는 코드에는 반드시 호출 예산 가드레일을 건다.
> `docs/saramin-jobcount-batch-strategy.md` 의 `max-api-calls` 패턴을 재사용한다.

## 3. 통계표 다운로드 (채택 경로)

### 3-1. 경로 — **확인됨**

```
EIS > 노동시장현황 > 구인구직 > 구인구직취업현황(월)
https://eis.work24.go.kr/eisps/rpt/reptDtl.do?menuId=020010010
```

> **`menuId=050010010`(주제별 통계 > 직종별 구인구직취업현황(월))을 쓰지 말 것.**
> 축이 `마감년월/직종중분류/직종소분류` 로 고정이고 지역은 **시도 단위 필터**라 시군구를 못 뽑는다.

`020010010` 은 고정 표가 아니라 **피벗 빌더**다. 왼쪽 분석항목을 행/열/측정값에 드래그해 축을 만든다.

**분석항목**: 마감년도 · 마감년월 · (근무지역)시도 · (근무지역)시군구 · **(지역별)시도** ·
**(지역별)시군구** · **직종\_중분류** · 직종\_소분류 · 산업\_대분류 · 고용형태 · 규모 · 성별 · 연령 · 학력

**측정값**: 구인인원(월) · 구직건수(월) · 취업건수(월)

### 3-2. 다운로드 절차

1. 위 URL 접속 (로그인 불필요)
2. 행에 `(지역별)시도`, `(지역별)시군구`, `직종_중분류` 배치 / 열에 `마감년월` 유지
3. 조회기간을 **12개월 범위**로 설정 (예: `202508` ~ `202607`)
4. 조회(돋보기) 실행 → 10초 내외
5. 다운로드 아이콘 → **XLSX**
6. `data/raw/eis/eis-job-<시작>-<종료>.xlsx` 로 저장

> **36개월을 한 번에 걸면 안 된다.** 엑셀 생성이 1분 넘게 끝나지 않아 취소했다(실측).
> **12개월 단위**는 안정적으로 완료된다.

지역 필터는 시도 다중선택이라 서울 제외가 가능하지만, **전국으로 받는 것을 권장한다.**
`JobScorePolicy` 가 최대값을 100점으로 두고 나머지를 비율 환산하므로 기준점이 될 지역이 필요하다.
수도권을 빼고 상대 비교하면 척도가 흔들린다. **수집은 전국, 필터는 화면에서.**

### 3-3. 확보된 파일 — **확인됨**

```
data/raw/eis/
├── eis-job-202308-202407.xlsx     1.5MB   9,233행   2018직종만      구인/구직/취업
├── eis-job-202408-202507.xlsx     2.5MB  17,823행   2018+2025 혼재  구인/구직/취업
├── eis-job-202508-202607.xlsx     1.5MB   9,322행   2025직종만      구인/구직/취업
├── eis-valid-202308-202407.xlsx   1.0MB              2018직종만      유효구인/유효구직
├── eis-valid-202408-202507.xlsx   1.7MB              2018+2025 혼재  유효구인/유효구직
└── eis-valid-202508-202607.xlsx   1.0MB              2025직종만      유효구인/유효구직
```

`eis-job-*` 는 `menuId=020010010`, `eis-valid-*` 는 `menuId=020010020` 에서 받는다.
두 리포트의 피벗 설정은 동일하다.

`.gitignore` 의 `/data/*` 에 걸려 git 추적되지 않는다. 변환 결과 시드 CSV 만 커밋한다.

## 4. 엑셀 파일 구조 — **확인됨**

12개월 파일 기준 `A1:AM9322` (39열).

| 영역 | 내용 |
| --- | --- |
| 상단 메타 | `출처: 한국고용정보원 고용행정통계`, 다운로드 시각, 필터 조건(`조회기간_fr/to`, `지역`) |
| 헤더 행(13행) | 월 라벨(`2025년 08월` …). **병합 셀** |
| A열 | (지역별)시도 |
| B열 | (지역별)시군구 |
| C열 | 직종\_중분류 (`2018직종_` / `2025직종_` 접두사 포함) |
| D열~ | 월 × 3측정값 반복 (12개월 = 36열) |

### 4-1. 파싱 시 주의

- **월 헤더가 병합 셀이다.** 월마다 `구인인원 / 구직건수 / 취업건수` 3열이 반복되는 구조를
  명시적으로 다뤄야 한다. 오프셋을 잘못 잡으면 값이 조용히 어긋난다.
- **소계 행을 반드시 제외한다.** `서울 전체`, `서울특별시 종로구 전체` 같은 행이 데이터 행과
  섞여 있다. 걸러내지 않으면 이중 집계된다. 판별 기준은 지역명이 ` 전체` 로 끝나는지.
- 파일 안에 출처 문자열이 들어 있어 **라이선스가 요구하는 출처 표시 근거가 파일 자체에 남는다.**

## 5. 코드 체계 정합성

### 5-1. 시군구 — 이름으로 매칭해야 한다

**엑셀에는 지역 코드가 없다.** `서울특별시 종로구` 같은 문자열뿐이다(API 는 `rsdAreaCd=11110` 을 준다).
따라서 이름 → `sigungu_code` 매칭 테이블이 필요하다.

실측 대조 결과 (`data/static/sigungu.csv` 272건 vs EIS 260건, 소계 제외):

| 구분 | 수 | 내용 |
| --- | --- | --- |
| 이름 일치 | **235** | 그대로 매칭 |
| 프로젝트에만 | 15 | 수원·성남·고양·안산·안양·용인·창원·포항·천안·청주·전주 등 **구가 있는 시의 상위 레벨**(EIS 는 구 단위만 제공, 시 레벨은 소계 행), 세종특별자치시(단층제라 시군구 축에 없음), 제주시 |
| EIS 에만 | 3 | `전주시덕진구` 등 **띄어쓰기 차이** |

### 5-2. 전남·광주 행정구역 통합

**2026년 7월 1일 전남광주통합특별시 출범.** 광주광역시 + 전라남도가 40년 만에 다시 합쳐졌고,
행정표준코드 배열 순서도 새로 확정됐다(양 시·도가 '시·구·군' 체계에 합의해 행안부 보고).

EIS 는 이들을 `전남광주통합특별시` 27개 시군구로 부르고, `sigungu.csv` 는 광주광역시 5개 +
전라남도 22개로 갖고 있다. **시군구 27개는 이름 기준 1:1 로 존치**됐다(실측, 차집합 0).
통합은 상위 시도 레벨의 재편이고 시군구 자체는 그대로다.

| 확인됨 | 미확인 |
| --- | --- |
| 시행일 2026-07-01 | **시군구 코드(29xxx/46xxx)가 유지됐는지** |
| 27개 이름 1:1 존치 | 새 시도 코드 값 |

> 코드 유지 여부는 EIS API 로 확인하려 했으나 §2-3 의 IP 한도에 걸려 당일 검증하지 못했다.
> **쿼터가 리셋된 날 `rsdAreaCd=46110`(목포시), `29110`(광주 동구)을 조회해 확정할 것.**

> 이것이 `memory/molit-jeonnam-gwangju-missing.md` 의 **"MOLIT 전남·광주 3종 API 전면 0건"**
> 원인일 가능성이 있다. 통합 시행(2026-07-01)과 결측 시작 시점이 맞는지 대조할 것.
> 다만 시군구 이름이 그대로 남았으므로 **시도 코드만 바뀌고 시군구 코드는 유지됐을 가능성**도 있다.
> 확정 전까지는 가설로 둔다.

**매칭 시 주의.** 27개 중 `동구·서구·남구·북구` 는 부산·대구·인천·대전·울산에도 있는 흔한 이름이다.

### 8-1. 새로 가능해지는 것

### 9-5. 알려진 공백

**시드 272개 중 264개 매칭. 누락 8개는 전부 구가 있는 시의 상위 레벨이다.**

```
41110 수원시  41130 성남시  41170 안양시  41270 안산시
41280 고양시  41460 용인시  43110 청주시  47110 포항시
```

EIS 는 구 단위만 제공하고 시 레벨은 소계 행으로만 낸다(소계는 제외 대상). **결측이 아니라
계층 중복이므로, 시 레벨이 필요하면 구 합계로 파생**하면 된다.

행 수가 이론상 조합(264 × 13 × 36 = 123,552)보다 3,852 적다. **EIS 가 0건 조합의 행을
아예 내지 않기 때문이다.** "데이터 없음"과 "0"은 다르므로 파서는 0으로 채우지 않는다.
점수 계산에서 0 취급이 필요하면 소비하는 쪽에서 판단한다.

### 9-6. 기존 시드와의 관계 — **미결정**

`JobCountCsvRow` 는 `(sigunguCode, middleCode, count)` 3열이고 `middleCode` 는 직종 **중분류**다.
EIS 로는 **대분류까지만** 채울 수 있고 월·다지표 개념도 없다. 형태가 맞지 않는다.

그래서 이 스크립트는 `data/generated/job_count.csv` 를 덮어쓰지 않고 별도 파일을 낸다.
아래 중 하나를 정해야 기존 배치에 연결할 수 있다.

1. `job_count.csv` 스키마를 확장한다(기준월·지표 컬럼 추가) — **DB 스키마 변경이므로 승인 필요**
2. 대분류 코드를 `middleCode` 자리에 넣는다 — `JobCode` 는 2·3자리를 모두 받으므로 통과하지만,
   조회 측이 중분류를 기대하면 의미가 어긋난다
3. 최신월 + 단일 지표만 뽑아 기존 3열 형태로 축약한다 — 시계열·구인배수를 버린다
